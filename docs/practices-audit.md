| **C1** Identity resolved server-side; client actor/ACL discarded `[all]` **(load-bearing)** | PASS | `api/schemas.py::PlanRequestModel` carries no `actor` field; `api/security.py::get_principal` builds a `RequestContext` from headers and resolves a verified `Principal` via the active `IdentityPort` on every route; failure is a 401; `plan.build_plan(request, actor=principal.actor)`. The IAP refusal is now split by whose failure it is, and the split is read at the API. In `adapters/gcp/iap_identity.py` the `MKT_CAMPAIGN_IAP_AUDIENCE` check already ran before the assertion header was read, so what changed here is the type it raises and the answer that follows: `IapAudienceUnconfiguredError`, not a plain `IdentityError`; the lazy google-auth import moved inside a `try` and raises `IapVerifierUnavailableError`. Both subclass `EndUserAuthUnavailableError` (declared in `ports/identity.py`, carrying `http_status`) and both answer 503, while an absent or blank assertion header stays a plain `IdentityError` and a bare 401 "authentication required" that tells a caller nothing they could forge with. `ctx.header(...)` is now `.strip()`ped, so a header a proxy or a deployment template rendered blank is refused as MISSING instead of reaching the algorithm pin. `api/security.py::get_principal` orders the `EndUserAuthUnavailableError` branch BEFORE the `IdentityError` branch, and the order is load-bearing: it is a subclass, so the reverse silently swallows it and answers the 401 the whole split exists to avoid. `tests/unit/test_iap_refusal_split.py` guards all of it. RED first, offline against the adapter exactly as it shipped: an unset audience gave `IdentityError: MKT_CAMPAIGN_IAP_AUDIENCE is not configured; cannot verify IAP assertion` whether or not the caller presented an assertion, and `api/security.py` answered 401 "authentication required" to it, sending an operator after a credential no credential would have supplied; a `"   "` header gave `IdentityError: assertion is not a compact JWS or JWE, so it carries no readable algorithm header`, a malformed token reported for an absent one; and with the `[gcp]` extra blocked, `ModuleNotFoundError: No module named 'google.auth.transport'` escaped `resolve` and `get_principal` for a bare 500 per request. The new module does not import against that tree at all; with only the two `Iap*Error` types injected and the old behaviour left standing it scored 8 failed / 3 passed, and reordering the two `except` branches on the fixed tree leaves 10 passed and fails `test_the_api_answers_a_deployment_failure_with_its_own_status_and_message` alone, 401 where 503 is owed. The fourth divergence from the `adapters/gcp/identity.py` family, the `principals` tuple, was investigated and deliberately NOT changed: this adapter grants `user:<subject>` and that family grants nothing, and it is this one that agrees with `hex_service_kit.federation.principal_from_iap_claims`, so aligning it would strip a verified identity of its own principal and widen nothing. The divergence is recorded in the test module rather than closed in the wrong direction. |
